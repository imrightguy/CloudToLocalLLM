# SESSION_RECOVERY_PLAN.md

Use this when starting a fresh session, after reinstall, or when context feels thin.

If you only need a quick reentry, read `SESSION_REENTRY.md` first.

## Goal

Recover fast without making Christopher repeat stable facts.

## Startup Order

1. Read local startup files:
   - `AGENTS.md`
   - `SOUL.md`
   - `USER.md`
   - recent daily memory files
   - `MEMORY.md` in main session
2. Read `RECOVERY.md`
3. If identity, preferences, or continuity need verification, use the Notion recovery notebook in this order:
   - `Read Me First`
   - `Current Snapshot`
   - `Identity`
   - `User Profile`
   - `Operating Preferences`
   - `Durable Memory`
   - `Projects`
4. Rebuild or verify local files if needed:
   - `IDENTITY.md`
   - `USER.md`
   - `MEMORY.md`
   - other durable docs as needed

## Rules

- Prefer reading known sources over asking settled questions again.
- Ask only when information is missing, stale, conflicting, or needs confirmation.
- Keep confirmed facts separate from inferred ones.
- Sync durable changes back into Notion when they matter for future recovery.
- Do not store secrets in Notion.

## Fast Summary

- Notion = durable external recovery anchor
- Workspace = live runtime layer
- Memory files = short-term and curated local continuity

## Current Intent

A new session should be able to recover who Zoidbot is, who Christopher is, how to behave, and what matters now with minimal friction.
